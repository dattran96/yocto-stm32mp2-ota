## 20a Lint and parse check

[`.github/workflows/ci.yml`](../.github/workflows/ci.yml) runs on every push and pull request, on
GitHub's `ubuntu-24.04` runners, with `permissions: contents: read`. No keys and no passwords are
available there, and none are needed:

| Job | What | Time (first run) |
|---|---|---|
| `lint` | `oelint-adv` 9.11.2: a report of all findings, then a gate that fails on errors | 11 s |
| `parse` | kas 5.5, `kas-container shell kas/stm32mp25-disco.yml -c "bitbake -p"` | 3 min |

- [`scripts/lint.sh`](../scripts/lint.sh) runs the same checks locally: `scripts/lint.sh` (gate)
  or `scripts/lint.sh --report`. The rules it switches off are listed there with the reason. Most
  are false alarms: the linter does not know ST's and meta-oe's variables and overrides
  (`stm32mpcommon`, `FLASHLAYOUT_*`, `VERITY_*`).
- One switched-off rule is a real finding, `oelint.vars.noncoreoverride`: the bbappends change
  dropbear, U-Boot, RAUC and others for every distro, not only `mydistro`. That is also what
  `yocto-check-layer` checks; it is a plan item.
- The parse job uses only `kas/stm32mp25-disco.yml`, without `kas/signing.yml`: parsing needs no
  keys. `kas-container` runs BitBake in kas's container image, which has the host tools Yocto
  needs, so the workflow has no own package list.

Locally, the parse check is:
```
cd ~/Dokumente/yocto/kas-work
~/kas-venv/bin/kas shell ../meta-mylayer/kas/stm32mp25-disco.yml -c "bitbake -p"
```
**Expected:** `Parsing of 2555 .bb files complete ... 0 errors.` (This rewrites `local.conf`
without the signing settings; the next `kas build` with `kas/signing.yml` writes them again.)

Check a run:
```
GH_HOST=github.com gh run list -R dattran96/yocto-stm32mp2-ota -L 3
```
**Expected:** `completed success` for the last push; the badge at the top of the README is green.

## Errors you may see
- `git push`: `refusing to allow an OAuth App to create or update workflow ... without 'workflow'
  scope`. The `gh` login may push code but not workflow files. Fix:
  `gh auth refresh -h github.com -s workflow` (browser login as the repository owner).
